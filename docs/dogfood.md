# Dogfood walkthrough: one real render → apply → teardown cycle

Captured verbatim from a real run on 2026-06-10, agent-profile 0.1.0 (debug
build), macOS. The cycle ran in a sandbox so it is reproducible by anyone:

```bash
# sandbox: a scratch HOME and a scratch git repo with the example workspace
SANDBOX="$(mktemp -d)"
export HOME="$SANDBOX/home"; export XDG_CONFIG_HOME="$HOME/.config"
unset CLAUDE_CONFIG_DIR CODEX_HOME GITHUB_PAT_RO GITHUB_PAT_RW
mkdir -p "$HOME/.agents/skills/code-review" "$HOME/.agents/skills/verification-before-completion"
echo "# code-review skill" > "$HOME/.agents/skills/code-review/SKILL.md"
echo "# vbc skill" > "$HOME/.agents/skills/verification-before-completion/SKILL.md"

REPO="$SANDBOX/repo"; mkdir -p "$REPO"
cp -R <agent-profile checkout>/examples/.agent-profile "$REPO/.agent-profile"
cd "$REPO"
git init -q .
printf '.agent-profile/state.json\n.agent-profile/backups/\n' > .gitignore
git add -A && git commit -qm baseline
```

Everything below is unedited command output from that sandbox (only the jq
quoting is normalized for readability). `scripts/smoke.sh` runs this same
cycle for all three targets with exit-code assertions; this document shows
what it actually looks like.

```text

  merge-keys  .claude/settings.local.json                    + [permissions.allow[+4]]  + [permissions.deny[+2]]  + [permissions.defaultMode]

  skipped model.effort: claude-teammate has no per-teammate effort control
          → set effortLevel in your own settings if needed
```

Note the honest `skipped` line (nothing is silently dropped) and the
project-wide-settings limitation note (see
[`docs/integrations.md`](integrations.md) for the worktree pattern that
collapses it).

```text

```

This is where the orchestrator would spawn the worker. To prove reversal is
key-level (not a blind file restore), we make a foreign edit while the
session is active — exactly what another tool or teammate might do:

```text
$ jq '.mcpServers["my-own-server"] = {"command":"my-mcp"}' .mcp.json > .mcp.json.new \
    && mv .mcp.json.new .mcp.json
```

## 5. Teardown — reverse replay, foreign edits survive

```text
$ agent-profile teardown --session-id loop-42-reviewer
  remove   CLAUDE.md                                      (block session=loop-42-reviewer)
  unlink   .claude/skills/verification-before-completion
  unlink   .claude/skills/code-review
  restore  .claude/settings.local.json                    (removed 4 allow rules, 2 deny rules, defaultMode)
  restore  .mcp.json                                      (removed keys mcpServers.docs-search, mcpServers.github-readonly)
  delete   .claude/agents/reviewer.md
✓ session loop-42-reviewer torn down, backups deleted
(exit 0)

$ cat .mcp.json   # foreign key survived, our keys gone
{
  "mcpServers": {
    "my-own-server": {
      "command": "my-mcp"
    }
  }
}

$ git status --porcelain   # only the foreign .mcp.json edit remains
?? .mcp.json

$ agent-profile current
ACTIVE SESSIONS
  (none)
(exit 0)
```

Without the deliberate foreign edit, `git status --porcelain` is empty after
teardown — the repo round-trips byte-identically (this is asserted by
`scripts/smoke.sh` and the `apply_teardown` integration suite on every CI
run).

## Rough edges noticed while dogfooding

Recorded here so they are known, not silently absorbed (sprint S5-T6).
Fixed in-sprint (the captures above show the fixed output):

1. The `merge-keys` explainer line in `render` human output said "via
   toml_edit" even for JSON targets (`.mcp.json`, `settings.local.json`,
   where the merge is `serde_json` key-level). Now wording matches the file
   format.
2. `apply` human output column alignment wobbled by one space around the
   `append-block` op (12-char op name vs an 11-char column). Now aligned.

Known, deliberately left (human-output-only, data is in `--json`):

3. `current` prints only `HH:MM:SS` of `appliedAt`; for sessions older than
   a day the date is invisible in human output (it is always in `--json`,
   and doctor's F071 flags >24h sessions).

None of these block the orchestrator contract.
